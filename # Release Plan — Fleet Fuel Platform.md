# Release Plan — Fleet Fuel Platform

##  Goal

The goal of this release is to deliver a complete JavaFX-based fleet fuel management application. The system will allow users to sign up and sign in, manage vehicles, record fuel purchases, track fuel efficiency and fuel costs, and view emissions reports. All main data will be stored in a database, and appropriate testing will be carried out throughout development.

## Sprint 1 — Authentication and Vehicle Management  
**Timeline: Weeks 7–8**

The first sprint will focus on setting up the main structure of the application. Users will be able to sign up, sign in and manage vehicle records. The team will also establish database storage and create the main JavaFX navigation structure.

By the end of this sprint, the main functions required for the Week 9 preliminary prototype should be working and ready to demonstrate.

## Sprint 2 — Fuel Logging and Efficiency Calculations  
**Timeline: Weeks 9–10**

The second sprint will focus on fuel-related functions. Users will be able to record fuel purchases and link each fuel record to a vehicle.

The system will also calculate fuel efficiency in L/100 km and track fuel costs. Input validation will be improved, and more integration testing will be added to make sure the new features work correctly with the existing parts of the application.

## Sprint 3 — Reports, Emissions and Continuous Integration  
**Timeline: Weeks 11–12**

The third sprint will focus on reporting and system integration. Users will be able to view summaries of fuel usage, fuel costs and CO₂ emissions.

Reporting and dashboard features will be added during this sprint. The team will also improve the development process by setting up automated builds, automated testing, GitHub Actions and Javadoc documentation.

By the end of this sprint, the application should provide a more complete view of fleet fuel performance and be supported by a more reliable testing and build process.

## Sprint 4 — Final Integration and Polish  
**Timeline: Week 13**

The final sprint will focus on completing and improving the application. All Must-Have user stories will be completed, and the team will review feedback from tutors and users.

Any remaining defects will be fixed, and usability and accessibility will be improved where needed. The team will also refactor parts of the code where necessary, complete final testing and documentation, and prepare the application for the final demonstration.

## Activities Across All Sprints

Throughout the project, the team will continue to review and prioritise user stories and acceptance criteria. Feature branches and pull requests will be used for development, with regular commits from each team member.

Test-driven development will be applied where appropriate. The project management board and sprint records will also be kept up to date so that progress can be tracked clearly.

Important design decisions, feedback and changes made during development will be recorded. The team will also make sure that the application remains buildable and demonstrable throughout the project.

## Major Release Milestones

**Week 9 — Preliminary Prototype**  
A functional preliminary prototype will be completed together with a video walkthrough.

**Week 11 — Enhanced Prototype**  
The application will include more complete functionality, together with build scripts, automated testing and continuous integration.

**Week 13 — Final Release**  
The final prototype, project archive, final walkthrough and presentation preparation will be completed.
