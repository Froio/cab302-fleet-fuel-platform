# Trello Board Plan

## Recommended workflow

Replace person-based lists with workflow-based lists:

```text
Product Backlog → Sprint 1 → In Progress → Review / Testing → Done
```

Use Trello **members** to show ownership instead of using one list per person.

## Sprint 1

Create separate cards for the Sprint 1 tasks in
`sprint-1-plan.md`. Avoid combining unrelated work into one very large card.

Each implementation card should ideally contain:

- related user-story ID;
- owner;
- estimate;
- acceptance criteria / definition of done;
- links or attachments to relevant designs;
- checklist of small implementation tasks.

## Suggested labels

- `Requirements`
- `UI / UX`
- `Implementation`
- `Database`
- `Testing`
- `Planning`

## Definition of Done for a typical implementation card

A card can move to `Done` when:

- acceptance criteria are met;
- code compiles;
- relevant automated tests pass where applicable;
- changes have been committed and pushed;
- another team member can review the work;
- documentation/design links are attached where useful.

## Week 7 evidence

For the checkpoint, the tutor should be able to see:

1. a visible product backlog;
2. a visible Sprint 1 selection;
3. task ownership;
4. task estimates;
5. cards moving through a workflow;
6. completed and in-progress work that matches GitHub evidence.
